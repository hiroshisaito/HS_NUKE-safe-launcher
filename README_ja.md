# Nuke セーフランチャー（uistate 肥大化ガード）

**NukeX の起動前に `~/.nuke/uistate.ini` を掃除する**ダブルクリック起動用ランチャーです。
Qt の「オーディオデバイス名が自己倍増する」不具合によって `uistate.ini` が肥大化し、
スプラッシュ画面で Nuke がハングする状態を防ぎます。

English: [`README.md`](README.md)

## なぜ必要か

日本語 Windows では、Nuke の `uistate.ini`（Qt の `QSettings` INI ファイル）が、
ローカライズされたオーディオ出力デバイス名（例: `スピーカー`）を `[audio] device=` に保存します。
Qt のコーデック往復（UTF-8 で書き、Latin-1 で読む）によって、この値は**起動のたびに倍の長さになります**。
**Nuke 15 (Qt5)** と **Nuke 16 (Qt6)** は同じ `~/.nuke/uistate.ini` を共有するため、
交互に使うと倍増が加速します。約24回の起動で値は約 240 MB に達し、Nuke はその解析中にハングします。

これは Qt/Nuke 側の不具合（QTBUG-54510 の系統）であり、**`HS_nkBrowser` の不具合ではありません**。
公式の修正が無いため、外側から防ぎます — Nuke が起動していない間に暴走した値をリセットします。

## ランチャーが毎回行うこと

1. Nuke プロセスが既に起動していれば注意書きを表示します（掃除が「定着」するのは
   すべての Nuke インスタンスを閉じた後のため）。**ブロックはしません。**
2. `HOME` / `HOMEDRIVE+HOMEPATH` / `USERPROFILE` の下にある各 `.nuke/uistate.ini` について
   （存在するものすべて。Windows の Nuke は `.nuke` を `HOME` から先に解決します）、
   **1 MB を超える行**（暴走した値）を削除します。それ以外 — ウィンドウレイアウト、
   ファイルブラウザ履歴、環境設定 — は**バイト単位でそのまま保持**されます。
   問題の無いファイルは**書き換えません**。書き換える場合は原子的に行い
   （一時ファイル + `File.Replace`）、元のファイルを `uistate.ini.presanitize.bak` として残します。
3. 指定されたメジャーバージョンの NukeX を起動します。

判定は**行の長さという汎用的な基準**で行い、オーディオ固有ではありません。
将来 `[FileBrowser]` の日本語プロジェクトパスなど別の非 ASCII が種になっても、同じように捕まえます。

## 起動するビルドを選ぶ

同じメジャーバージョンのビルドが2つ入っている場合 — 例えば `16.1v2` と `16.1v3` —
ランチャーは指定が無ければ新しい方を起動します。何が入っているかを見るには:

```
powershell -ExecutionPolicy Bypass -File "nuke_safe_launch.ps1" -Major 16 -ListVersions
```

```
[nuke-safe-launch] Nuke 16.x builds on this machine:
    16.1v3     D:\Program Files\Nuke16.1v3\Nuke16.1.exe   <- newest
    16.1v2     D:\Program Files\Nuke16.1v2\Nuke16.1.exe
```

その回だけ特定のビルドを起動する:

```
... -Major 16 -Version 16.1v2
```

設定として覚えさせる（以降 `NukeX 16 (safe).bat` のダブルクリックでそれが起動します）:

```
... -Major 16 -Version 16.1v2 -SetDefault
```

設定はユーザーごと・マシンごとに `~/.nuke/hs_nuke_launcher.json` へ保存されます
（`hs_nkbrowser_config.json` の隣）。**このスクリプトの隣ではありません** —
`launchers` フォルダはリポジトリからコピーされたり共有から直接実行されたりするため、
そこに置くと1台の選択が全台に及んでしまうからです。
「新しい方」に戻すには、該当エントリ（またはファイル）を削除してください。

優先順位は上から順に `-Exe` → `-Version` → 保存された既定 → 最新のインストール。

「インストールされていない」2つのケースは、意図的に挙動を分けています。

- **自分で指定した `-Version`** が一致しない場合は**エラー**です。インストール済みの
  一覧を表示して停止します。指定したのと別のビルドが起動することこそ、
  このオプションが防ごうとしている問題だからです。`-SetDefault` も同じ文字列を拒否します。
- **保存された既定**が後からアンインストールされていた場合は**警告のみ**で、最新版を起動します。
  古いビルドを消したことで、それを設定していた全員が作業できなくなっては困るからです。

## ファイル構成

| ファイル | 役割 |
|------|---------|
| `nuke_safe_launch.ps1` | 本体。掃除 + exe 解決 + 起動。 |
| `NukeX 15 (safe).bat`  | ダブルクリック → 掃除 → NukeX 15 |
| `NukeX 16 (safe).bat`  | ダブルクリック → 掃除 → NukeX 16 |
| `NukeX 17 (safe).bat`  | ダブルクリック → 掃除 → NukeX 17 |

## 使い方

使いたいバージョンの `.bat` をダブルクリックします。コンソールウィンドウが
一瞬表示され（掃除の結果が出ます）、NukeX が起動します。
エラー時（その Nuke バージョンが未インストール等）はウィンドウが
メッセージを表示したまま残ります。

`.nk` を `.bat` にドロップしたり、コマンドラインで渡したりもできます。
オプションとして認識されない引数は、そのまま Nuke へ渡されます。

### 別のマシンへ配置する

`launchers` フォルダごと対象マシンの任意の場所にコピーしてください
（ネットワークやリポジトリから直接実行しても構いません）。**編集は不要です。**

- Nuke の実行ファイルは、そのマシンの**スタートメニューのショートカット**
  （Foundry インストーラが作る正規のパス）**と**、すべての固定ドライブの
  `Program Files` の**両方**から探して統合します。同順位の場合はスタートメニュー側を
  優先するので、既定で起動するのはインストーラが登録したビルドのままです。
  （以前はスタートメニューで見つからないときだけ `Program Files` を見ていたため、
  ショートカットのないビルドが見えませんでした。「どれを起動するか」だけならそれでもよくても、
  ユーザーが選べるようになった今は困ります。）
- `uistate.ini` のパスは `HOME` / `USERPROFILE` に従うため、スタジオが `HOME` を
  設定している環境でも動作します。

### デスクトップショートカット

各 `.bat` を右ドラッグでデスクトップへ → *ショートカットをここに作成*。
既存のショートカットのリンク先を `.bat` に向けても構いません。
（ショートカットのアイコンを Nuke の exe に設定すると、見た目を揃えられます。）

## 詳細オプション（`nuke_safe_launch.ps1`）

```
-Major 15|16|17     起動する NukeX のバージョン（exe は自動検出）
-Exe <path>         特定の exe を起動（非標準のインストール先など）。-Major より優先
-Mode nukex|studio|assist|nuke   起動モード（既定 nukex）
-Version <x.yvZ>    このビルドを起動する。例 16.1v2（「起動するビルドを選ぶ」参照）
-ListVersions       -Major で指定したメジャーのインストール済みビルドを一覧して終了
-SetDefault         -Version を既定として記憶し、そのまま起動する
-MaxLineChars <n>   肥大化とみなす行長のしきい値（既定 1048576 = 1 MB）
-AbortLaunchOverMB <n>  掃除に失敗し、かつ uistate がこのサイズを超えている場合、
                        起動を中止する（既定 16 MB）。起動してもハングするため
-NoLaunch           掃除のみ行い Nuke を起動しない（テスト用）
-UiStatePath <path> 特定の uistate.ini を掃除する（テスト用）
-SearchRoot <path>  Start Menu + Program Files ではなくこの場所を探索する
                    （テスト用。同一メジャーの実インストールが2つある機は稀なため）
<追加引数>          Nuke へそのまま渡される（開きたい .nk など）
```

例 — 非標準のインストール先から NukeX を起動し、コンプを開く:

```
powershell -ExecutionPolicy Bypass -File "nuke_safe_launch.ps1" -Exe "C:\Apps\Nuke16.0v6\Nuke16.0.exe" "C:\path\to comp.nk"
```

## 注意事項・制限

- **先にすべての Nuke インスタンスを閉じてください。** Nuke が起動していると終了時に
  `uistate.ini` を書き戻すため、掃除が取り消される可能性があります
  （ランチャーはこの点を警告します）。
- 管理が厳しいマシンでは、**グループポリシー**が `-ExecutionPolicy Bypass` を上書きすることがあります。
  その場合はポリシー側で `.ps1` を許可する必要があります。
- バックアップ: 掃除直前のコピーが `uistate.ini` の隣に `*.presanitize.bak` として残ります。
